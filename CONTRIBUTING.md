# Участие в проекте

## С чего начать

```bash
npm install
npm run dev
```

Понадобится Node из `.nvmrc` (22) или новее. Ничего больше ставить не нужно:
внешних ресурсов проект не тянет, текстур в нём нет.

## Что должно быть зелёным

```bash
npm run typecheck   # tsc --noEmit
npm test            # юнит-тесты, vitest
npm run e2e         # сквозные, Playwright + Chromium
```

Те же три проверки гоняет CI на каждый pull request, и без них ветка не
сливается.

## Как здесь принято

**Проверяемость важнее полноты.** У каждой задачи в плане работ есть поле «чем
проверяется», и это не формальность: половина найденных здесь дефектов
выглядела совершенно правдоподобно. Кольца Сатурна месяц рисовались поверх
планеты, и заметил это человек, разглядывая картинку в описании, — все 199
тестов при этом были зелёными.

Поэтому:

- то, у чего есть правильный ответ, проверяется юнит-тестом (положения тел
  сверяются с выгрузкой JPL Horizons);
- то, что живёт только в браузере, — сквозным (скомпилировались ли шейдеры,
  попадает ли клик по Юпитеру в Юпитер, а не в Ганимед);
- если изменилась картинка, снимки перегенерируются: `node scripts/shots.mjs`
  при поднятом dev-сервере.

**Комментарии объясняют «почему», а не «что».** Что делает строка, видно из
строки. Ценно другое: почему крен выключен, почему сглаживание скорости
логарифмическое, почему билборд вынесен вперёд собственной сферы. Если решение
неочевидно — его стоит объяснить; если очевидно — комментарий лишний.

**Числа берутся из источников.** Радиусы, массы, элементы орбит и вращения — из
таблиц JPL и отчётов МАС, со ссылкой в комментарии. Подгоночных констант ради
картинки в проекте нет, и заводить их не стоит: как только появится первая,
доверять перестанешь всем остальным.

**Язык — русский.** Интерфейс, комментарии, сообщения коммитов. Это выбор, а не
недоделка; подробнее — в разделе «Язык» описания.

## Коммиты и ветки

`main` защищена: прямой push отклоняется, изменения идут через pull request с
зелёными проверками.

Сообщение коммита — связный текст, а не префикс с одной строкой. Заголовок
говорит, что меняется; тело — почему так, а не иначе, и что при этом
выяснилось. Conventional commits здесь не используются.

## Планы

Что имеет смысл делать дальше — в [ROADMAP.md](ROADMAP.md) и на доске задач.
Если беретесь за пункт оттуда, стоит сказать об этом в задаче: так никто не
сделает то же самое второй раз.
